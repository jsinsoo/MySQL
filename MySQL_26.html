1. 성취기준과 학습 목표

성취기준

저장 프로시저의 개념과 활용 목적을 이해하고, 반복되는 SQL 업무를 프로시저로 정의하여 호출할 수 있다.

IN·OUT·INOUT 매개변수, 조건문, 반복문, 오류 처리와 트랜잭션을 활용하여 입력값을 검증하고 안전하게 데이터를 처리하는 프로시저를 구현할 수 있다.

학습 목표

  1. 저장 프로시저의 필요성과 장점을 설명한다.
  2. CREATE PROCEDURE, DELIMITER, CALL을 사용한다.
  3. IN·OUT·INOUT 매개변수를 구분하여 활용한다.
  4. IF, CASE, WHILE, SIGNAL, 트랜잭션을 결합한 프로시저를 작성한다.

3. 수업 시작 이야기

📚 인문학자의 이야기 — 문명은 기억을 절차로 남긴다

인류는 중요한 일을 개인의 기억에만 맡기지 않았습니다. 농사의 시기, 의례의 순서, 법의 집행 절차를 기록하여 다음 세대도 같은 원칙을 이어 갈 수 있게 했습니다.

저장 프로시저는 데이터베이스의 경험을 절차로 남깁니다. 반복되는 업무를 한 사람의 손기술이 아니라 모두가 공유할 수 있는 지식으로 바꿉니다.

🏛 철학자의 이야기 — 원칙은 상황 속에서 작동해야 한다

철학적 원칙은 아름다운 문장에 머물 때보다 실제 상황에서 판단 기준이 될 때 힘을 가집니다. 무엇을 받아들이고, 무엇을 거부하며, 어떤 경우에 다르게 행동할지 정해야 합니다.

프로시저의 매개변수와 조건문은 원칙을 실행 가능한 판단으로 바꿉니다. 입력에 따라 같은 가치가 다른 행동으로 나타납니다.

🔬 과학자의 이야기 — 재현 가능한 절차가 신뢰를 만든다

과학 실험은 결과보다 과정이 분명해야 합니다. 다른 사람이 같은 조건과 순서를 따라 했을 때 비슷한 결과가 나와야 신뢰할 수 있습니다.

저장 프로시저는 데이터 처리 과정을 표준화합니다. 누가 호출하더라도 같은 검증과 같은 순서가 적용되어 데이터의 신뢰도를 높입니다.

➗ 수학자의 이야기 — 함수는 복잡함을 이름 하나로 다룬다

수학자는 긴 계산 과정을 함수라는 이름으로 묶습니다. 입력이 달라지면 결과도 달라지지만, 계산 규칙은 흔들리지 않습니다.

저장 프로시저도 입력 매개변수를 받고 정해진 SQL 절차를 수행합니다. 복잡한 업무를 짧은 CALL 한 줄로 실행하게 하는 데이터베이스의 함수적 사고입니다.

교사의 시작 이야기

오늘의 목표는 긴 SQL을 숨기는 것이 아닙니다. 반복되는 업무를 누구나 이해하고 믿을 수 있는 절차로 설계하는 것입니다. 좋은 프로시저에는 입력값의 의미, 잘못된 값에 대한 대응, 성공과 실패의 기준이 담겨 있습니다. 여러분이 만드는 프로시저는 단순한 코드가 아니라 데이터베이스에게 건네는 책임 있는 업무 설명서입니다.

    FROM students
    ORDER BY student_id;

IN 매개변수로 학년별 조회

IN 매개변수는 호출할 때 외부에서 값을 전달받습니다. 같은 프로시저라도 입력한 학년에 따라 다른 학생 목록을 반환합니다.

DELIMITER //

    IN p_grade INT
)
BEGIN

           student_name,
           grade
    FROM students
    WHERE grade = p_grade
    ORDER BY student_name;

04

OUT 매개변수로 결과 반환

IN 매개변수로 학생 번호를 받고, 계산된 평균을 OUT 매개변수로 돌려줍니다. SELECT ... INTO를 이용해 조회 결과를 변수에 저장합니다.

DELIMITER //

CREATE PROCEDURE get_average_score(
    IN p_student_id INT,
    OUT p_average DECIMAL(5,2)
)
BEGIN
    SELECT AVG(score)
    INTO p_average
    FROM scores
    WHERE student_id = p_student_id;
END //

DELIMITER ;

CALL get_average_score(101, @avg_score);
SELECT @avg_score AS average_score;

05

INOUT 매개변수로 값 변경

INOUT 매개변수는 입력값을 받아 내부에서 수정한 뒤 다시 외부로 전달합니다. LEAST 함수로 점수가 100을 넘지 않도록 제한합니다.

DELIMITER //

CREATE PROCEDURE apply_bonus(
    INOUT p_score INT,
    IN p_bonus INT
)
BEGIN
    SET p_score = LEAST(p_score + p_bonus, 100);
END //

DELIMITER ;

SET @my_score = 88;
CALL apply_bonus(@my_score, 5);
SELECT @my_score;

06

IF문으로 입력값 검증

점수 범위를 검사하여 잘못된 값이면 SIGNAL로 사용자 정의 오류를 발생시키고, 올바른 값일 때만 INSERT를 수행합니다.

DELIMITER //

CREATE PROCEDURE register_score(
    IN p_student_id INT,
    IN p_subject VARCHAR(20),
    IN p_score INT
)
BEGIN
    IF p_score < 0 OR p_score > 100 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '점수는 0부터 100 사이여야 합니다.';
    ELSE
        INSERT INTO scores(student_id, subject, score)
        VALUES (p_student_id, p_subject, p_score);
    END IF;
END //

DELIMITER ;

CALL register_score(101, '과학', 95);

CASE문으로 성취 수준 판정

CASE 표현식을 사용하여 점수 구간별 성취 수준을 반환합니다. 여러 조건을 순서대로 검사하므로 높은 점수 조건부터 작성합니다.

DELIMITER //

CREATE PROCEDURE evaluate_score(
    IN p_score INT
)
BEGIN
    SELECT CASE
        WHEN p_score >= 90 THEN 'A'
        WHEN p_score >= 80 THEN 'B'
        WHEN p_score >= 70 THEN 'C'
        WHEN p_score >= 60 THEN 'D'
        ELSE '보충 학습'
    END AS achievement_level;
END //

DELIMITER ;

CALL evaluate_score(84);

08

WHILE 반복문과 지역 변수

DECLARE로 지역 변수 i를 선언하고 WHILE문으로 1부터 입력값까지 반복합니다. 반복할 때마다 i를 증가시켜 무한 반복을 방지합니다.

DELIMITER //

CREATE PROCEDURE make_practice_numbers(
    IN p_limit INT
)
BEGIN
    DECLARE i INT DEFAULT 1;

    WHILE i <= p_limit DO
        SELECT i AS practice_number;
        SET i = i + 1;
    END WHILE;
END //

DELIMITER ;

CALL make_practice_numbers(3);

09

트랜잭션을 포함한 성적 수정

UPDATE 결과가 정확히 한 행일 때만 COMMIT하고, 그렇지 않으면 ROLLBACK과 오류를 실행합니다. 프로시저와 트랜잭션을 결합한 안전한 수정 예입니다.

DELIMITER //

CREATE PROCEDURE safe_update_score(
    IN p_student_id INT,
    IN p_subject VARCHAR(20),
    IN p_new_score INT
)
BEGIN
    START TRANSACTION;

    UPDATE scores
    SET score = p_new_score
    WHERE student_id = p_student_id
      AND subject = p_subject;

    IF ROW_COUNT() = 1 THEN
        COMMIT;
    ELSE
        ROLLBACK;
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '수정할 성적을 정확히 찾지 못했습니다.';
    END IF;
END //

DELIMITER ;

CALL safe_update_score(101, '수학', 92);

5. 형성평가 OX 퀴즈 10개

1
저장 프로시저는 여러 SQL 문을 하나의 이름으로 묶어 재사용할 수 있다.
2
DELIMITER는 프로시저 본문 내부의 세미콜론과 전체 정의의 끝을 구분하는 데 도움을 준다.
3
IN 매개변수는 외부에서 프로시저 안으로 값을 전달한다.
4
OUT 매개변수는 프로시저 내부의 결과를 외부로 전달할 수 있다.
5
INOUT 매개변수는 입력과 출력 역할을 함께 수행한다.
6
저장 프로시저 내부에서는 IF, CASE, WHILE을 사용할 수 없다.
7
SIGNAL은 업무 규칙에 맞지 않는 경우 사용자 정의 오류를 발생시키는 데 사용할 수 있다.
8
프로시저 안에서 트랜잭션을 사용해 안전한 수정 절차를 만들 수 있다.
9
DROP PROCEDURE를 실행하면 관련 테이블과 데이터도 모두 삭제된다.
10
입력값 검증과 권한 관리는 저장 프로시저의 안전성과 관련이 없다.

6. 수업 끝 이야기

🌙 시인의 이야기 — 반복되는 후렴에도 이유가 있다

좋은 시와 노래의 후렴은 같은 말을 되풀이하지만 매번 새로운 마음을 불러옵니다. 프로시저도 같은 절차를 반복하지만 입력에 따라 다른 결과를 만듭니다. 단, 시험 점수를 100으로 만드는 프로시저는 선생님의 권한 검사를 통과하기 어렵습니다.

📖 소설가의 이야기 — 인물의 선택에는 일관된 규칙이 있다

설득력 있는 인물은 아무 이유 없이 행동하지 않습니다. 경험과 성격이 선택의 기준이 됩니다. 저장 프로시저도 데이터가 상황마다 제멋대로 움직이지 않도록 일관된 행동 규칙을 제공합니다.

🎭 희곡인의 이야기 — 대본은 함께 움직이기 위한 약속이다

대본은 배우의 자유를 없애는 종이가 아니라 서로 다른 사람들이 같은 장면을 완성하게 하는 약속입니다. 프로시저 역시 여러 사용자가 같은 업무 규칙을 따르도록 돕습니다.

🎬 연극인의 이야기 — 한마디의 큐 사인 뒤에는 수많은 준비가 있다

“조명 시작!”이라는 짧은 신호 뒤에는 밝기, 순서, 음악, 무대 전환이 연결되어 있습니다. CALL 한 줄도 마찬가지입니다. 짧지만 그 안에는 세심하게 설계된 절차가 숨어 있습니다.

🎼 음악인의 이야기 — 좋은 반복은 리듬이 되고 나쁜 반복은 소음이 된다

반복되는 박자는 음악을 만들지만 끝나지 않는 반복은 연주자를 지치게 합니다. WHILE문에는 반드시 끝나는 조건이 필요합니다. 앙코르도 세 번쯤이면 감동이고 서른 번이면 귀가 시간이 걱정됩니다.

오늘의 오래 남는 마지막 이야기

성장은 매번 새로운 일을 시작하는 데서만 오지 않습니다. 자주 하는 일을 더 정확하고 친절하며 안전한 절차로 다듬는 과정에서도 성장합니다.

여러분의 공부에도 작은 프로시저를 만들어 보십시오. 시작할 시간을 정하고, 이해되지 않을 때 질문하는 IF문을 넣고, 지치면 잠시 쉬는 예외 처리도 준비하십시오. 꿈은 한 번의 거대한 실행보다 좋은 절차를 꾸준히 CALL할 때 가까워집니다. 오늘 작성한 한 줄의 프로시저처럼 여러분의 노력도 언젠가 누군가에게 믿을 수 있는 길이 될 것입니다.
