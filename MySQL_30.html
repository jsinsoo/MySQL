3. 수업 시작 이야기

📚 인문학자의 이야기 — 기록은 쌓는 것보다 돌보는 일이 더 중요하다

도서관은 책을 받아 적재하는 곳에 머물지 않습니다. 새 책을 등록하고, 필요한 책을 찾고, 잘못된 정보를 수정하며, 폐기할 자료를 구분합니다. 데이터 관리도 같은 흐름을 가집니다.

CRUD는 프로그램의 네 가지 명령이 아니라 기록을 책임 있게 돌보는 기본 태도입니다.

🏛 철학자의 이야기 — 존재하게 하고, 이해하고, 변화시키고, 놓아주는 일

우리는 무언가를 만들고, 바라보고, 고치고, 때로는 떠나보냅니다. CREATE, READ, UPDATE, DELETE도 디지털 세계에서 존재를 다루는 네 가지 기본 행동입니다.

중요한 것은 가능한 행동을 아는 것뿐 아니라 언제 어떤 행동을 해야 하는지 판단하는 것입니다.

🔬 과학자의 이야기 — 실험 기록은 생성·관찰·수정·정리의 순환이다

과학자는 실험 데이터를 만들고 관찰하며, 잘못 기록된 값을 수정하고, 의미 없는 중복 자료를 정리합니다. 그 과정에서 원본과 변경 이유를 신중하게 다룹니다.

오늘의 CRUD 실습은 데이터에 대한 정확성과 책임을 함께 배우는 작은 연구 과정입니다.

➗ 수학자의 이야기 — 연산은 규칙이 있을 때 안전해진다

수학의 연산은 대상과 조건이 명확해야 올바른 결과를 냅니다. 데이터 수정과 삭제도 어떤 행을 대상으로 할지 WHERE 조건을 분명히 해야 합니다.

조건 없는 DELETE가 두려운 이유는 수학에서 정의역을 확인하지 않고 계산하는 것과 비슷합니다.

교사의 시작 이야기

오늘부터 데이터베이스는 화면 속 표가 아니라 여러분이 직접 움직이는 프로그램이 됩니다. 입력 버튼 하나는 새로운 기록을 만들고, 조회 기능은 필요한 사람을 찾으며, 수정은 실수를 바로잡고, 삭제는 더 이상 필요하지 않은 정보를 정리합니다. 그러나 힘이 커질수록 책임도 커집니다. 특히 UPDATE와 DELETE 앞에서는 한 번 더 조건을 읽는 습관을 들이십시오. 좋은 개발자는 빠르게 실행하는 사람이 아니라 데이터가 어떤 결과를 맞게 될지 생각하고 실행하는 사람입니다.

학생 정보 입력 CREATE

03

전체 학생 조회 READ

SELECT와 fetchall()을 사용하여 모든 학생 정보를 조회합니다. dictionary=True를 사용하면 열 이름으로 값을 읽을 수 있습니다.

def show_all_students():
    conn = get_connection()
    cur = conn.cursor(dictionary=True)

    cur.execute('''
    SELECT student_id,
           name,
           score
    FROM students
    ORDER BY student_id
    ''')

    rows = cur.fetchall()

    for row in rows:
        print(
            row["student_id"],
            row["name"],
            row["score"]
        )

    cur.close()
    conn.close()

학생 한 명 조회 READ

WHERE 조건과 fetchone()으로 한 명의 학생을 조회합니다. 결과가 없을 때 None을 확인하여 사용자에게 안내합니다.

def find_student(student_id):
    conn = get_connection()
    cur = conn.cursor(dictionary=True)

    cur.execute(
        '''
        SELECT student_id,
               name,
               score
        FROM students
        WHERE student_id = %s
        ''',
        (student_id,)
    )

    student = cur.fetchone()

    if student is None:
        print("학생을 찾을 수 없습니다.")
    else:
        print(student)

    cur.close()
    conn.close()

05

학생 점수 수정 UPDATE

UPDATE와 WHERE를 사용하여 특정 학생의 점수를 수정합니다. rowcount로 실제 변경 대상이 있었는지 확인합니다.

def update_score(student_id, new_score):
    conn = get_connection()
    cur = conn.cursor()

    cur.execute(
        '''
        UPDATE students
        SET score = %s
        WHERE student_id = %s
        ''',
        (new_score, student_id)
    )

    conn.commit()

    if cur.rowcount == 0:
        print("수정할 학생이 없습니다.")
    else:
        print("점수 수정 완료")

    cur.close()
    conn.close()

학생 정보 삭제 DELETE

DELETE와 WHERE를 사용하여 특정 학생만 삭제합니다. WHERE가 빠지면 전체 행이 삭제될 수 있으므로 매우 주의해야 합니다.

def delete_student(student_id):
    conn = get_connection()
    cur = conn.cursor()

    cur.execute(
        '''
        DELETE FROM students
        WHERE student_id = %s
        ''',
        (student_id,)
    )

    conn.commit()

    if cur.rowcount == 0:
        print("삭제할 학생이 없습니다.")
    else:
        print("학생 정보 삭제 완료")

    cur.close()
    conn.close()

점수 입력 검증

문자열 입력을 정수로 변환하고 0~100 범위를 검사합니다. 잘못된 입력을 데이터베이스에 저장하기 전에 차단합니다.

def validate_score(score_text):
    try:
        score = int(score_text)

        if not 0 <= score <= 100:
            raise ValueError(
                "점수는 0~100이어야 합니다."
            )

        return score

    except ValueError as error:
        print("입력 오류:", error)
        return None

score = validate_score(input("점수: "))

08

트랜잭션과 롤백

입력 과정에서 오류가 발생하면 rollback()으로 변경을 취소합니다. finally에서는 성공 여부와 관계없이 자원을 정리합니다.

def add_student_safely(
    student_id,
    name,
    score
):
    conn = get_connection()
    cur = conn.cursor()

    try:
        cur.execute(
            '''
            INSERT INTO students
            VALUES (%s, %s, %s)
            ''',
            (student_id, name, score)
        )

        conn.commit()
        print("저장 완료")

    except mysql.connector.Error as error:
        conn.rollback()
        print("저장 실패:", error)

    finally:
        cur.close()
        conn.close()

def main():

5. 형성평가 OX 퀴즈 10개

1
CRUD는 Create, Read, Update, Delete의 약자이다.
2
데이터를 입력하거나 수정한 뒤에는 일반적으로 commit()으로 변경을 확정한다.
3
SELECT 실행 결과 여러 행을 가져올 때 fetchall()을 사용할 수 있다.
4
특정 행을 수정하거나 삭제할 때 WHERE 조건을 신중하게 사용해야 한다.
5
Prepared Statement 방식은 사용자 입력을 SQL 구조와 분리하는 데 도움이 된다.
6
rowcount는 INSERT, UPDATE, DELETE로 영향을 받은 행 수를 확인하는 데 활용할 수 있다.
7
오류 발생 시 rollback()을 사용하면 확정되지 않은 변경을 취소할 수 있다.
8
finally 블록은 오류가 발생했을 때만 실행된다.
9
입력값 검증은 잘못된 데이터가 저장되는 것을 줄이는 데 도움이 된다.
10
CRUD 프로그램에서는 연결과 커서를 닫지 않아도 항상 안전하다.

6. 수업 끝 이야기

🌙 시인의 이야기 — 지우고 고치는 순간에도 문장은 성장한다

시인은 첫 문장을 그대로 두지 않습니다. 더 정확한 단어로 바꾸고 불필요한 구절을 덜어 내며 작품을 완성합니다. UPDATE와 DELETE도 올바른 목적과 조건을 만날 때 데이터를 더 선명하게 만듭니다. 단, WHERE를 잊으면 시집 전체가 백지가 될 수 있습니다.

📖 소설가의 이야기 — 인물의 변화가 이야기를 움직인다

소설 속 인물은 처음 모습 그대로 머물지 않습니다. 경험을 통해 수정되고 새로운 관계를 만들어 갑니다. 데이터도 현실의 변화를 반영할 때 살아 있는 기록이 됩니다.

🎭 희곡인의 이야기 — 등장과 퇴장에는 이유가 있어야 한다

무대에서 인물이 등장하고 퇴장하는 데는 장면의 목적이 있습니다. 데이터의 CREATE와 DELETE에도 분명한 이유와 조건이 필요합니다. 아무 배우나 퇴장시키면 다음 장면의 JOIN이 매우 외로워집니다.

🎬 연극인의 이야기 — 무대 뒤의 동선이 자연스러워야 관객이 편하다

좋은 공연은 관객이 무대 전환의 어려움을 느끼지 않게 합니다. 좋은 CRUD 프로그램도 복잡한 SQL을 숨기고 이해하기 쉬운 메뉴와 안내를 제공합니다.

🎼 음악인의 이야기 — 네 가지 동작이 하나의 리듬이 된다

음악은 음을 시작하고, 듣고, 조정하고, 멈추는 흐름 속에서 완성됩니다. CREATE, READ, UPDATE, DELETE도 조화롭게 연결될 때 하나의 서비스가 됩니다. DELETE만 계속 연주하면 현대음악에서도 꽤 과감한 편입니다.

오늘의 오래 남는 마지막 이야기

프로그램을 만든다는 것은 명령을 실행하는 일이 아니라 누군가의 기록과 시간을 다루는 일입니다. 작은 오타 하나를 수정해 주는 기능은 누군가에게 신뢰가 되고, 필요한 정보를 빠르게 찾아 주는 조회는 누군가의 기다림을 줄여 줍니다.

여러분의 삶도 CRUD처럼 성장합니다. 새로운 꿈을 만들고, 지난 경험을 돌아보고, 부족한 점을 고치고, 자신을 가로막는 두려움을 내려놓으십시오. 단, 실패한 경험까지 모두 삭제하지는 마십시오. 그 기록은 다음 선택을 더 현명하게 만드는 가장 귀한 데이터입니다.
