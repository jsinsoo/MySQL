1. 성취기준과 학습 목표

성취기준

데이터 무결성의 의미를 이해하고 기본키, 외래키, 고유성, 필수값, 범위, 기본값에 관한 업무 규칙을 제약 조건으로 표현할 수 있다.

CREATE TABLE과 ALTER TABLE을 이용하여 제약 조건을 생성·확인·변경하고, 잘못된 데이터 입력을 예방할 수 있다.

학습 목표

  1. 제약 조건과 데이터 무결성의 관계를 설명한다.
  2. PRIMARY KEY, UNIQUE, NOT NULL의 차이를 구분한다.
  3. CHECK와 DEFAULT를 이용해 값의 규칙을 설계한다.
  4. FOREIGN KEY로 참조 무결성을 구현하고 제약 조건을 관리한다.

일반화: 제약 조건은 업무 규칙을 데이터베이스 구조에 직접 반영하여 잘못된 데이터가 저장되기 전에 차단하고, 여러 사용자가 데이터를 다루더라도 일관성과 신뢰성을 유지하게 한다.

핵심 질문: 어떤 값은 반드시 있어야 하는가, 무엇은 중복되면 안 되는가, 어떤 범위만 허용할 것인가, 어떤 부모 데이터와 연결되어야 하는가?

3. 수업 시작 이야기

📚 인문학자의 이야기 — 자유를 지키는 약속

사람들은 규칙을 자유의 반대라고 생각하기도 합니다. 그러나 서로의 권리를 지키는 약속이 없다면 강한 사람의 자유만 남고, 약한 사람의 자유는 사라질 수 있습니다.

데이터베이스의 제약 조건도 입력을 무조건 막기 위한 벽이 아닙니다. 잘못된 데이터 때문에 전체 시스템의 신뢰가 무너지지 않도록 지켜 주는 공동의 약속입니다.

🏛 철학자의 이야기 — 경계는 정체성을 만든다

철학에서는 어떤 것이 무엇인지 설명할 때 그것이 무엇이 아닌지도 함께 밝힙니다. 경계가 있어야 개념이 분명해집니다.

점수는 0점에서 100점 사이이고, 학생 번호는 중복되지 않으며, 이름은 비어 있지 않아야 한다는 경계가 데이터의 정체성을 만듭니다.

🔬 과학자의 이야기 — 측정값에도 유효 범위가 있다

과학자는 센서가 기록한 값이라고 해서 모두 사실로 받아들이지 않습니다. 온도가 갑자기 천만 도로 기록되었다면 측정 범위와 장비 상태를 확인합니다.

CHECK와 NOT NULL은 데이터가 들어오는 순간 유효성을 검사하여 분석 이전에 오류를 발견하게 합니다.

➗ 수학자의 이야기 — 정의역 밖의 값은 함수의 답이 아니다

함수에는 입력 가능한 값의 범위인 정의역이 있습니다. 정의역 밖의 값을 넣으면 올바른 결과를 기대할 수 없습니다.

제약 조건은 데이터베이스의 정의역을 정합니다. 허용되는 값의 집합을 분명히 하여 계산과 판단의 신뢰성을 높입니다.

교사의 시작 이야기

오늘 배울 제약 조건은 학생을 감시하는 규칙과 다릅니다. 실수로 1000점을 입력하거나, 존재하지 않는 학생에게 성적을 연결하거나, 같은 이메일을 여러 번 등록하는 일을 데이터베이스가 먼저 막아 주는 안전장치입니다. 좋은 제약 조건은 사용자를 불편하게 만드는 것이 아니라 사용자의 실수를 조용히 보호합니다.

05

CHECK로 점수 범위 제한

점수가 0점부터 100점 사이에만 저장되도록 CHECK 제약 조건을 설정합니다. 범위를 벗어난 값은 입력이나 수정 과정에서 거부됩니다.

CREATE TABLE scores (
    score_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    subject VARCHAR(30) NOT NULL,
    score INT NOT NULL,
    CHECK (score BETWEEN 0 AND 100)

06

FOREIGN KEY로 참조 무결성 설정

수강 테이블의 학생 번호와 과목 번호가 실제 부모 테이블에 존재하도록 외래키를 설정합니다. 존재하지 않는 학생이나 과목의 수강 기록을 막습니다.

CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course_id INT NOT NULL,
    FOREIGN KEY (student_id)
        REFERENCES students(student_id),
    FOREIGN KEY (course_id)
        REFERENCES courses(course_id)
);

07

복합 UNIQUE 제약 조건

같은 장소가 같은 날짜와 교시에 중복 예약되지 않도록 세 열의 조합에 UNIQUE를 적용합니다.

CREATE TABLE reservations (
    reservation_id INT AUTO_INCREMENT PRIMARY KEY,
    room_id INT NOT NULL,
    reservation_date DATE NOT NULL,
    period_no INT NOT NULL,
    UNIQUE (room_id, reservation_date, period_no)

08

이름을 붙인 CHECK 제약 조건

가격과 재고가 음수가 되지 않도록 이름 있는 CHECK 제약 조건을 정의합니다. 이름을 지정하면 오류 확인과 제약 조건 관리가 쉬워집니다.

CREATE TABLE products (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(50) NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    stock INT DEFAULT 0,
    CONSTRAINT chk_product_price
        CHECK (price >= 0),
    CONSTRAINT chk_product_stock
        CHECK (stock >= 0)
);

5. 형성평가 OX 퀴즈 10개

1
제약 조건은 데이터가 정해진 규칙을 지키도록 제한하는 장치이다.
2
PRIMARY KEY는 각 행을 유일하게 식별하며 NULL을 허용하지 않는다.
3
한 테이블에는 PRIMARY KEY를 여러 개 독립적으로 지정할 수 있다.
4
UNIQUE는 특정 열이나 열 조합의 중복을 제한한다.
5
NOT NULL은 반드시 값이 입력되도록 한다.
6
DEFAULT는 값이 생략될 때 사용할 기본값을 지정한다.
7
CHECK는 입력값이 논리 조건을 만족하는지 검사한다.
8
FOREIGN KEY는 부모 테이블에 없는 값을 자유롭게 입력하도록 한다.
9
복합 UNIQUE는 여러 열의 조합을 기준으로 중복을 제한할 수 있다.
10
제약 조건은 테이블 생성 시에만 설정할 수 있고 나중에는 추가할 수 없다.

6. 수업 끝 이야기

🌙 시인의 이야기 — 운율에도 지켜야 할 박자가 있다

시는 자유롭지만 아무 글자나 흩뿌린다고 모두 시가 되지는 않습니다. 제약 속에서 리듬을 만들 때 문장이 오래 남습니다. 다만 CHECK를 너무 많이 걸면 시인도 입력 거부를 당할 수 있습니다.

📖 소설가의 이야기 — 주인공의 이름은 장마다 바뀌지 않는다

첫 장의 주인공이 둘째 장에서 이유 없이 다른 이름으로 등장하면 독자는 당황합니다. UNIQUE와 PRIMARY KEY는 등장인물의 정체성을 끝까지 지켜 주는 편집자입니다.

🎭 희곡인의 이야기 — 무대의 안전선은 배우를 가두지 않는다

무대의 표시선은 배우의 자유를 빼앗기 위한 것이 아니라 어둠 속 추락을 막기 위한 것입니다. 데이터 제약 조건도 멋진 실행을 위한 보이지 않는 안전선입니다.

🎬 연극인의 이야기 — 소품은 제자리에 있어야 한다

왕관이 냉장고 안에 있고 검이 객석에 있다면 창의적인 연극일 수는 있지만 진행은 어려워집니다. DEFAULT와 FOREIGN KEY는 필요한 소품을 제자리에 둡니다.

🎼 음악인의 이야기 — 쉼표도 규칙이다

음악에서 쉼표는 아무것도 하지 않는 시간이 아니라 다음 음을 살리는 약속입니다. NOT NULL은 빈칸을 막지만, 때로는 NULL을 허용하는 지혜도 필요합니다. 모든 악기가 쉬지 않으면 음악도 데이터베이스도 숨이 찹니다.

오늘의 오래 남는 마지막 이야기

삶의 제약은 때때로 우리를 답답하게 합니다. 시간, 환경, 실패, 책임은 마음대로 없앨 수 없는 조건처럼 느껴집니다. 그러나 모든 제약이 꿈을 막는 벽은 아닙니다.

어떤 제약은 방향을 잃지 않게 하는 난간이고, 어떤 원칙은 나를 지키는 기본키입니다. 할 수 없는 일만 바라보기보다 지금의 조건 안에서 할 수 있는 가장 좋은 선택을 찾아보십시오. 여러분의 가능성에는 CHECK 제약이 없습니다. 다만 자신의 가치와 타인의 존엄을 지키는 아름다운 제약만 오래 간직하기 바랍니다.
