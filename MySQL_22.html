MySQL 22차시
뷰(View)

복잡한 조회를 가상 테이블로 단순화하고, 사용자별 정보 접근 범위를 제한하며, 안전하고 재사용 가능한 데이터 관점을 설계합니다.

1. 성취기준과 학습 목표

성취기준

뷰의 개념과 원본 테이블과의 관계를 이해하고, 단순 조회·조건 조회·조인·집계 결과를 가상 테이블로 정의할 수 있다.

뷰를 활용하여 복잡한 질의를 재사용하고 정보 접근 범위를 제한하며, 뷰를 생성·변경·조회·삭제할 수 있다.

학습 목표

  1. 뷰와 실제 테이블의 차이를 설명한다.
  2. CREATE VIEW로 단순·조건·조인·집계 뷰를 생성한다.
  3. 뷰를 활용해 복잡한 조회를 단순화하고 민감한 열을 제한한다.
  4. ALTER VIEW, CREATE OR REPLACE VIEW, WITH CHECK OPTION, DROP VIEW를 활용한다.

3. 수업 시작 이야기

📚 인문학자의 이야기 — 같은 세계도 창문에 따라 다르게 보인다

도시는 하나이지만 도서관 창문에서 바라본 풍경과 운동장 창문에서 바라본 풍경은 다릅니다. 창문은 도시를 새로 만들지 않지만, 필요한 장면을 선택해 보여 줍니다.

데이터베이스의 뷰도 원본 세계를 복사하지 않고 목적에 맞는 데이터의 창을 만듭니다. 학생에게는 학습 정보만, 행정 담당자에게는 업무 정보만 보여 줄 수 있습니다.

🏛 철학자의 이야기 — 관점은 사실을 없애지 않고 의미를 조직한다

철학자는 하나의 사건도 관점에 따라 다르게 해석될 수 있다고 말합니다. 그러나 관점이 달라진다고 사실 자체가 사라지는 것은 아닙니다.

뷰는 원본 데이터를 바꾸지 않으면서 사용 목적에 맞는 관점을 제공합니다. 중요한 것은 관점이 진실을 왜곡하지 않고 필요한 의미를 분명하게 드러내는 것입니다.

🔬 과학자의 이야기 — 관측 장비는 필요한 신호를 선택한다

과학자는 모든 파장을 한꺼번에 보지 않습니다. 망원경의 필터와 현미경의 배율을 조절하여 연구 목적에 필요한 신호를 선택합니다.

뷰는 데이터베이스의 관측 장비입니다. 복잡한 원본 구조에서 필요한 열과 행만 선택하여 분석과 판단을 더 정확하게 만듭니다.

➗ 수학자의 이야기 — 함수는 입력 전체를 새로운 표현으로 보여 준다

함수는 같은 입력 집합을 목적에 맞는 출력으로 변환합니다. 원래 값은 존재하지만 우리는 계산에 필요한 결과를 중심으로 바라봅니다.

뷰도 SELECT라는 규칙을 통해 원본 테이블을 새로운 결과 집합으로 표현합니다. 조인, 조건, 집계는 뷰를 만드는 수학적 변환과 같습니다.

교사의 시작 이야기

오늘 우리는 데이터를 더 많이 저장하는 법이 아니라, 이미 저장된 데이터를 더 지혜롭게 보여 주는 법을 배웁니다. 좋은 뷰는 복잡한 SQL을 줄이고, 실수를 예방하며, 개인정보가 불필요하게 노출되는 일을 막습니다. 모든 사람에게 모든 정보를 보여 주는 것이 투명성은 아닙니다. 필요한 사람에게 필요한 정보를 정확하게 보여 주는 것이 책임 있는 데이터 활용입니다.

01

기본 뷰 생성

학생 테이블에서 자주 사용하는 기본 열만 선택해 가상 테이블을 만듭니다. 실제 데이터는 원본 테이블에 저장되고 뷰는 SELECT 문의 결과 구조를 제공합니다.

CREATE VIEW student_basic_view AS
SELECT student_id,
       student_name,
       grade
FROM students;

03

조인 결과를 뷰로 저장

여러 테이블을 조인한 복잡한 조회를 하나의 뷰로 정의합니다. 이후에는 뷰를 하나의 테이블처럼 조회할 수 있어 SQL이 단순해집니다.

CREATE VIEW enrollment_summary_view AS
SELECT s.student_name,
       c.course_name,
       e.score
FROM enrollments AS e
JOIN students AS s
  ON e.student_id = s.student_id
JOIN courses AS c
  ON e.course_id = c.course_id;

04

집계 결과 뷰 생성

학년별 평균 점수와 학생 수를 계산한 집계 뷰입니다. 반복되는 GROUP BY와 집계 함수를 재사용할 수 있습니다.

CREATE VIEW class_average_view AS
SELECT grade,
       AVG(score) AS average_score,
       COUNT(*) AS student_count
FROM scores
GROUP BY grade;

6. 수업 끝 이야기

🌙 시인의 이야기 — 창문은 벽에 낸 짧은 시다

창문은 세상 전체를 담지 않지만 한 조각의 빛으로 방 전체를 바꿉니다. 뷰도 모든 열을 보여 주지 않지만 필요한 정보만으로 충분한 의미를 만듭니다. 다만 창문을 너무 많이 열면 겨울에는 서버도 춥습니다.

📖 소설가의 이야기 — 모든 인물의 주민등록번호를 소개할 필요는 없다

좋은 소설은 장면에 필요한 정보만 보여 줍니다. 주인공이 아침을 먹는 장면에 데이터베이스 비밀번호까지 설명하면 독자도 작가도 지칩니다. 뷰는 이야기의 편집자입니다.

🎭 희곡인의 이야기 — 관객은 무대 뒤 창고까지 볼 필요가 없다

관객은 완성된 장면을 보고, 배우와 기술팀은 무대 뒤 구조를 압니다. 뷰는 복잡한 데이터의 무대 뒤를 감추고 필요한 장면만 정확하게 보여 줍니다.

🎬 연극인의 이야기 — 같은 무대도 조명에 따라 다른 장면이 된다

조명은 무대를 새로 만들지 않지만 인물과 감정을 다르게 드러냅니다. 뷰도 원본 테이블을 바꾸지 않고 목적에 맞는 장면을 비춥니다.

🎼 음악인의 이야기 — 믹서는 필요한 소리를 앞으로 보낸다

합주에는 수많은 소리가 있지만 믹서는 노래에 필요한 소리를 선명하게 만듭니다. 모든 채널을 최대로 올리면 음악이 아니라 소음이 됩니다. SELECT *도 가끔은 같은 운명을 만납니다.

오늘의 오래 남는 마지막 이야기

우리도 때때로 자신의 부족한 모습만 확대해서 바라봅니다. 그러나 한 번의 실패는 여러분 전체가 아니라 삶이라는 거대한 테이블에서 조회된 한 행일 뿐입니다.

오늘의 어려움만 보여 주는 뷰를 잠시 닫고, 지금까지 견뎌 온 용기와 앞으로 성장할 가능성을 함께 조회해 보십시오. 관점은 현실을 숨기는 도구가 아니라 현실 속 희망을 발견하는 창입니다. 여러분의 원본 데이터에는 아직 읽지 않은 수많은 가능성의 행이 남아 있습니다.
