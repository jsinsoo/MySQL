3. 수업 시작 이야기

📚 인문학자의 이야기 — 생각은 기록될 때 세계에 흔적을 남긴다

기획은 마음속의 가능성을 언어로 정리하는 과정이었고, 구현은 그 언어를 실제로 작동하는 형태로 바꾸는 과정입니다. 오래된 문명도 아이디어만 남은 것이 아니라 돌, 종이, 건축물과 기록으로 구현되었기에 오늘까지 전해집니다.

오늘 우리는 설계도에 있던 데이터와 관계를 실제 테이블과 프로그램으로 옮깁니다.

🏛 철학자의 이야기 — 가능성은 행동을 만날 때 현실이 된다

철학자는 인간이 어떤 가능성을 가지고 있는지만 묻지 않고, 그 가능성을 어떤 선택과 행동으로 실현하는지도 고민합니다. 프로젝트도 좋은 아이디어만으로 완성되지 않습니다.

작은 기능 하나를 실제로 작동시키는 일이 막연한 꿈을 현실로 바꾸는 첫 증거입니다.

🔬 과학자의 이야기 — 이론은 실험을 통해 검증된다

과학 이론은 실험과 관측을 통해 현실에서 확인됩니다. ERD와 기능 명세도 실제 데이터와 코드로 실행해 보아야 올바른 설계인지 알 수 있습니다.

구현 과정에서 발견되는 오류는 설계의 실패가 아니라 더 정확한 구조를 찾게 하는 실험 결과입니다.

➗ 수학자의 이야기 — 증명은 한 단계씩 연결된다

복잡한 정리도 정의, 가정, 논리적 단계가 연결되어 증명됩니다. 프로젝트 구현도 데이터베이스 생성, 테이블 정의, 샘플 데이터, 연결, 기능 구현의 순서를 따라야 안정적으로 완성됩니다.

작은 단계가 정확하면 전체 시스템도 신뢰할 수 있습니다.

교사의 시작 이야기

오늘은 계획서 속 문장들이 실제로 움직이기 시작하는 날입니다. 처음부터 거대한 프로그램을 만들 필요는 없습니다. 테이블 하나를 정확히 만들고, 샘플 데이터 한 건을 넣고, 조회 결과 한 줄을 성공적으로 출력하는 것이 중요합니다. 구현은 완벽함을 한 번에 얻는 일이 아니라 작동하는 작은 성공을 차곡차곡 연결하는 과정입니다.

08

예약 등록 기능

새 예약을 등록하고 commit()으로 저장합니다. lastrowid를 사용해 새로 생성된 예약 번호를 확인합니다.

def add_reservation(
    user_id,
    equipment_id,
    start_time,
    end_time
):
    conn = get_connection()
    cur = conn.cursor()

    sql = '''
    INSERT INTO reservations(
        user_id,
        equipment_id,
        start_time,
        end_time
    )
    VALUES (%s, %s, %s, %s)
    '''

    cur.execute(
        sql,
        (
            user_id,
            equipment_id,
            start_time,
            end_time
        )
    )

    conn.commit()
    reservation_id = cur.lastrowid

    cur.close()
    conn.close()

    return reservation_id

예약 현황 조인 조회

예약, 사용자, 장비 테이블을 조인해 사람이 이해하기 쉬운 예약 현황을 출력합니다.

def show_reservations():
    conn = get_connection()
    cur = conn.cursor(dictionary=True)

    cur.execute('''
    SELECT r.reservation_id,
           u.user_name,
           e.equipment_name,
           r.start_time,
           r.end_time,
           r.approval_status
    FROM reservations AS r
    INNER JOIN users AS u
        ON r.user_id = u.user_id
    INNER JOIN equipment AS e
        ON r.equipment_id = e.equipment_id
    ORDER BY r.start_time
    ''')

    rows = cur.fetchall()

    for row in rows:
        print(row)

    cur.close()
    conn.close()

6. 수업 끝 이야기

🌙 시인의 이야기 — 첫 문장은 작품 전체가 아니지만 작품을 시작한다

첫 문장이 완벽하지 않아도 시는 그 한 줄에서 시작됩니다. 1차 구현물도 완성품은 아니지만 꿈이 실행되기 시작한 첫 문장입니다. 단, 세미콜론을 잊으면 MySQL은 시적 여운을 인정하지 않고 계속 기다립니다.

📖 소설가의 이야기 — 초고는 고칠 수 있기 때문에 가치가 있다

소설가의 초고에는 어색한 장면과 부족한 설명이 있습니다. 그러나 초고가 있어야 수정도 가능합니다. 1차 구현물의 오류는 부끄러운 흔적이 아니라 개선할 수 있는 재료입니다.

🎭 희곡인의 이야기 — 대본은 배우의 움직임 속에서 완성된다

희곡은 종이 위에 있을 때와 무대에서 실행될 때가 다릅니다. 설계도도 코드로 실행해 보아야 실제 문제를 발견할 수 있습니다. 실행 버튼은 프로그램의 첫 공연을 알리는 막입니다.

🎬 연극인의 이야기 — 첫 리허설에서 넘어져도 공연은 끝나지 않는다

첫 리허설은 실수를 감추는 시간이 아니라 찾아내는 시간입니다. 오류 메시지는 야단치는 관객이 아니라 무대 위치를 알려 주는 조명입니다. 너무 빨간 조명이 많이 켜지면 잠깐 물을 마셔도 됩니다.

🎼 음악인의 이야기 — 한 음씩 맞추면 결국 합주가 된다

처음부터 모든 악기가 완벽하게 맞지는 않습니다. 데이터베이스, SQL, 파이썬 함수가 하나씩 제 박자를 찾을 때 프로그램은 하나의 곡처럼 움직입니다.

오늘의 오래 남는 마지막 이야기

꿈은 머릿속에 있을 때 아름답지만, 현실로 옮기는 순간 예상하지 못한 오류와 한계를 만납니다. 바로 그 순간이 꿈이 사라지는 때가 아니라 진짜 성장하기 시작하는 때입니다.

완벽한 결과를 기다리느라 시작을 미루지 마십시오. 오늘 작동한 작은 기능 하나는 내일의 큰 시스템보다 작아 보이지만, 실제로 존재한다는 점에서 훨씬 강합니다. 여러분의 가능성도 실행할 때 비로소 세상과 연결됩니다.
