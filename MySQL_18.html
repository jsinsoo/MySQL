서브쿼리

단일행·다중행·상관 서브쿼리와 IN, ANY, ALL, EXISTS를 활용하여 복잡한 질문을 단계적으로 해결합니다.

1. 성취기준과 학습 목표

성취기준

다른 SELECT 문 안에 포함된 서브쿼리의 실행 구조를 이해하고 단일행·다중행 서브쿼리를 작성할 수 있다.

IN, ANY, ALL, EXISTS와 상관 서브쿼리를 활용하여 평균 이상 학생, 특정 집합에 속한 자료, 관련 행의 존재 여부를 조회할 수 있다.

학습 목표

  1. 서브쿼리와 외부 쿼리의 관계를 설명한다.
  2. 단일행과 다중행 서브쿼리를 구분한다.
  3. IN, ANY, ALL의 의미를 비교한다.
  4. 상관 서브쿼리와 EXISTS를 이용해 복합 조건을 해결한다.

일반화: 서브쿼리는 복잡한 문제를 내부 질문과 외부 판단으로 나누어 해결하며, 내부 결과의 행 수와 의미에 따라 적절한 비교 연산자를 선택해야 한다.

3. 수업 시작 이야기

📚 인문학자의 이야기 — 질문 안에 또 다른 질문이 있다

인문학자는 하나의 문장을 이해하기 위해 그 문장이 태어난 시대와 사람, 숨은 전제를 다시 묻습니다. 겉으로 보이는 질문 안에 더 작은 질문이 들어 있는 셈입니다.

서브쿼리도 바깥 질문을 해결하기 위해 먼저 안쪽 질문의 답을 구합니다. “평균보다 높은 학생은 누구인가?”라는 질문은 먼저 “평균은 얼마인가?”를 물어야 완성됩니다.

🏛 철학자의 이야기 — 큰 답은 작은 답 위에 세워진다

철학은 복잡한 문제를 한 번에 붙잡기보다 전제를 나누고, 각각의 답을 다시 연결합니다. 생각의 층을 쌓는 일입니다.

서브쿼리는 SQL 안에 사고의 층을 만듭니다. 안쪽 질의가 근거를 만들고, 바깥 질의가 그 근거를 이용해 최종 판단을 내립니다.

🔬 과학자의 이야기 — 기준값을 먼저 계산한 뒤 비교한다

과학자는 이상값을 찾기 전에 평균, 기준 범위, 최대값 같은 기준을 계산합니다. 기준 없이 “높다”거나 “낮다”고 말할 수 없기 때문입니다.

서브쿼리는 평균과 최댓값 같은 기준을 먼저 구하고, 외부 쿼리가 각 데이터를 그 기준과 비교하도록 합니다.

➗ 수학자의 이야기 — 괄호 안의 계산부터

수학에서는 복잡한 식을 풀 때 괄호 안을 먼저 계산합니다. 괄호의 결과가 바깥 식의 판단 기준이 됩니다.

SQL의 서브쿼리도 괄호 안쪽 SELECT가 먼저 실행되고, 그 결과가 바깥 쿼리의 조건이나 임시 테이블로 사용됩니다.

교사의 시작 이야기

어려운 문제를 만났을 때 한 번에 정답을 찾으려 하면 생각이 엉킬 수 있습니다. 먼저 답할 수 있는 작은 질문을 만들고, 그 답을 다음 질문의 디딤돌로 사용해 보십시오. 서브쿼리는 데이터베이스 문법이면서 동시에 복잡한 문제를 차분하게 분해하는 사고법입니다.

01

평균 점수보다 높은 학생 조회

전체 평균 점수를 먼저 구한 뒤, 그 값보다 높은 점수를 가진 학생을 조회합니다. 하나의 값을 반환하는 단일행 서브쿼리입니다.

SELECT student_name, score
FROM scores
WHERE score > (
    SELECT AVG(score)
    FROM scores
);

평균 이상인 과목별 성적 조회

FROM scores AS s1
WHERE score >= (

06

ANY를 이용한 비교

수학 점수들 가운데 적어도 하나보다 높은 점수를 가진 행을 조회합니다. ANY는 서브쿼리 결과 중 하나라도 조건을 만족하면 참입니다.

SELECT student_name, score
FROM scores
WHERE score > ANY (
    SELECT score
    FROM scores
    WHERE subject = '수학'

08

FROM 절의 서브쿼리

서브쿼리 결과를 임시 테이블처럼 사용합니다. FROM 절의 서브쿼리는 반드시 별칭을 가져야 합니다.

SELECT class_id, avg_score
FROM (
    SELECT class_id, AVG(score) AS avg_score
    FROM scores
    GROUP BY class_id
) AS class_avg
WHERE avg_score >= 85;

09

EXISTS를 이용한 수강 여부 확인

학생에게 수강 기록이 하나라도 존재하는지 확인합니다. EXISTS는 실제 값보다 행의 존재 여부를 판단합니다.

SELECT s.student_id, s.student_name
FROM students AS s
WHERE EXISTS (
    SELECT 1
    FROM enrollments AS e
    WHERE e.student_id = s.student_id

5. 형성평가 OX 퀴즈 10개

1
서브쿼리는 다른 SQL 문 안에 포함된 SELECT 문이다.
2
단일행 서브쿼리는 하나의 값을 반환하는 경우가 일반적이다.
3
다중행 서브쿼리에는 IN, ANY, ALL 등을 사용할 수 있다.
4
서브쿼리는 WHERE 절에서만 사용할 수 있다.
5
상관 서브쿼리는 외부 쿼리의 값을 참조할 수 있다.
6
ANY는 서브쿼리 결과의 모든 값과 조건을 만족해야 참이다.
7
ALL은 서브쿼리 결과의 모든 값과 비교한다.
8
FROM 절의 서브쿼리에는 일반적으로 별칭이 필요하다.
9
EXISTS는 관련 행의 존재 여부를 검사한다.
10
NOT EXISTS는 관련 행이 하나라도 있을 때 참이다.

6. 수업 끝 이야기

🌙 시인의 이야기 — 괄호 안에도 별이 뜬다

짧은 괄호 안의 한 문장이 긴 시의 방향을 바꾸기도 합니다. 서브쿼리도 작은 괄호 안에서 최종 결과를 움직입니다. 단, 괄호를 닫지 않으면 시가 아니라 구문 오류가 오래 남습니다.

📖 소설가의 이야기 — 복선은 작은 서브쿼리다

소설의 초반에 나온 작은 단서가 마지막 장의 결말을 설명합니다. 서브쿼리도 먼저 구한 작은 결과로 바깥 이야기의 결론을 완성합니다.

🎭 희곡인의 이야기 — 무대 뒤 질문이 무대 앞 대사를 만든다

배우의 한마디 뒤에는 “왜 이 말을 하는가?”라는 보이지 않는 질문이 있습니다. SQL도 안쪽 질의가 준비되어야 바깥 질의가 자신 있게 결과를 말합니다.

🎬 연극인의 이야기 — 주인공도 조연의 답을 기다린다

주인공이 혼자 결말을 만들 수는 없습니다. 안쪽 쿼리라는 조연이 기준값을 건네야 바깥 쿼리가 멋진 마지막 장면을 완성합니다.

🎼 음악인의 이야기 — 작은 프레이즈가 큰 곡을 이끈다

짧은 선율이 반복되고 변주되며 한 곡의 중심이 됩니다. 서브쿼리의 작은 결과도 외부 쿼리의 흐름을 바꿉니다. 반복이 너무 많으면 공연도 쿼리도 느려질 수 있으니 박자를 살펴야 합니다.

오늘의 오래 남는 마지막 이야기

큰 꿈은 어느 날 갑자기 완성된 하나의 답이 아닙니다. 오늘 해결한 작은 질문, 어제 발견한 작은 기준, 실패 뒤에 다시 만든 작은 시도가 겹쳐져 만들어집니다.

여러분의 삶에도 답을 바로 내리지 못하는 순간이 있을 것입니다. 그때 자신을 틀렸다고 판단하지 말고, 먼저 풀 수 있는 작은 서브쿼리를 만들어 보십시오. “오늘 할 수 있는 것은 무엇인가?”, “어제보다 나아진 한 가지는 무엇인가?” 그 작은 답들이 모여 결국 여러분만의 가장 멋진 최종 SELECT 문을 완성할 것입니다.
