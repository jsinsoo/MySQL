1. 성취기준과 학습 목표

성취기준

사용자 정의 함수의 개념과 반환 구조를 이해하고 반복되는 계산 규칙을 함수로 작성하여 SQL 문에서 활용할 수 있다.

INSERT, UPDATE, DELETE 사건에 반응하는 트리거를 생성하고 NEW와 OLD를 활용하여 데이터 검증, 보정, 변경 이력 기록을 구현할 수 있다.

학습 목표

  1. 함수와 프로시저의 기본 차이를 설명한다.
  2. CREATE FUNCTION과 RETURN을 사용해 함수를 작성한다.
  3. BEFORE·AFTER 트리거의 실행 시점을 구분한다.
  4. NEW·OLD를 사용해 변경 전후 데이터를 검증하고 기록한다.

3. 수업 시작 이야기

📚 인문학자의 이야기 — 기록은 사건보다 오래 남는다

역사는 사건 자체만으로 남지 않습니다. 누군가가 언제 무엇이 바뀌었는지 기록했기 때문에 우리는 과거를 이해합니다.

트리거는 데이터베이스에서 일어난 변화를 자동으로 기록하는 작은 역사가입니다. 사용자가 기억하지 않아도 변화의 흔적을 남깁니다.

🏛 철학자의 이야기 — 원인과 결과 사이에는 규칙이 있다

철학은 어떤 사건이 왜 일어났고, 그 결과가 무엇인지 묻습니다. 데이터베이스에서도 입력·수정·삭제라는 사건 뒤에는 자동으로 이어져야 할 책임이 있습니다.

트리거는 사건과 반응을 연결하고, 함수는 같은 입력에 같은 판단을 제공하는 규칙의 언어입니다.

🔬 과학자의 이야기 — 센서는 변화를 감지하고 즉시 반응한다

온도 센서는 기준값을 넘는 순간 경보를 울리고, 실험 장치는 이상값을 감지하면 작동을 멈춥니다.

트리거도 데이터의 변화를 감지하여 검증, 보정, 기록을 자동 수행합니다. 데이터베이스 안의 센서이자 반응 장치입니다.

➗ 수학자의 이야기 — 함수는 입력과 출력의 약속이다

수학의 함수는 같은 입력에 대해 정해진 규칙에 따라 결과를 만듭니다. 복잡한 계산도 이름 하나로 다시 사용할 수 있습니다.

사용자 정의 함수는 데이터베이스 안에 계산 규칙을 저장하여 반복되는 판단을 일관된 결과로 바꿉니다.

교사의 시작 이야기

오늘 우리는 사용자가 직접 명령하지 않아도 데이터베이스가 스스로 판단하고 반응하게 만드는 방법을 배웁니다. 함수는 계산의 기준을 남기고, 트리거는 변화에 책임 있게 반응합니다. 좋은 자동화는 사람을 대신하는 것이 아니라 사람이 놓치기 쉬운 규칙을 조용히 지켜 주는 기술입니다.

4. 학습할 코드 10개와 상세 설명

01

숫자 값을 반환하는 사용자 정의 함수

입력받은 가격에 10%를 더한 값을 반환하는 사용자 정의 함수입니다. 함수는 RETURN 문을 통해 반드시 하나의 값을 돌려줍니다.

DELIMITER //

CREATE FUNCTION add_tax(
    p_price DECIMAL(10,2)
)
RETURNS DECIMAL(10,2)
DETERMINISTIC
BEGIN
    RETURN p_price * 1.10;
END //

DELIMITER ;

SELECT add_tax(10000) AS price_with_tax;

02

문자열을 반환하는 함수

점수를 입력받아 성취 수준을 문자열로 반환합니다. CASE 표현식을 사용해 여러 조건을 하나의 반환값으로 정리합니다.

DELIMITER //

CREATE FUNCTION score_level(
    p_score INT
)
RETURNS VARCHAR(20)
DETERMINISTIC
BEGIN
    RETURN CASE
        WHEN p_score >= 90 THEN '우수'
        WHEN p_score >= 70 THEN '보통'
        ELSE '보충 필요'
    END;
END //

DELIMITER ;

SELECT score_level(85) AS result;

05

BEFORE INSERT 트리거로 입력값 보정

점수가 입력되기 전에 NEW.score 값을 검사하여 0보다 작으면 0, 100보다 크면 100으로 보정합니다.

DELIMITER //

CREATE TRIGGER scores_before_insert
BEFORE INSERT ON scores
FOR EACH ROW
BEGIN
    IF NEW.score < 0 THEN
        SET NEW.score = 0;
    ELSEIF NEW.score > 100 THEN
        SET NEW.score = 100;
    END IF;
END //

DELIMITER ;

06

AFTER INSERT 트리거로 이력 기록

성적이 새로 입력된 뒤 score_logs 테이블에 자동으로 이력을 기록합니다. INSERT 트리거에서는 NEW를 통해 새 행의 값을 참조합니다.

DELIMITER //

CREATE TRIGGER scores_after_insert
AFTER INSERT ON scores
FOR EACH ROW
BEGIN
    INSERT INTO score_logs(
        action_type,
        student_id,
        subject,
        new_score,
        changed_at
    )
    VALUES(
        'INSERT',
        NEW.student_id,
        NEW.subject,
        NEW.score,
        NOW()
    );
END //

DELIMITER ;

07

BEFORE UPDATE 트리거로 변경 검증

수정 전에 새 점수의 범위를 검사하고, 잘못된 값이면 SIGNAL로 수정 작업을 중단합니다.

DELIMITER //

CREATE TRIGGER scores_before_update
BEFORE UPDATE ON scores
FOR EACH ROW
BEGIN
    IF NEW.score < 0 OR NEW.score > 100 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '점수는 0~100 범위여야 합니다.';
    END IF;
END //

DELIMITER ;

5. 형성평가 OX 퀴즈 10개

1
사용자 정의 함수는 RETURN을 통해 하나의 값을 반환한다.
2
사용자 정의 함수는 SELECT문에서 열 표현식처럼 사용할 수 있다.
3
트리거는 특정 테이블의 INSERT, UPDATE, DELETE 사건에 반응하여 자동 실행될 수 있다.
4
INSERT 트리거에서 새 행의 값은 NEW를 통해 참조할 수 있다.
5
DELETE 트리거에서 삭제된 행의 값은 OLD를 통해 참조할 수 있다.
6
BEFORE INSERT 트리거에서는 NEW 값을 절대로 변경할 수 없다.
7
AFTER UPDATE 트리거에서는 OLD와 NEW를 모두 사용할 수 있다.
8
SIGNAL은 업무 규칙에 맞지 않는 변경을 중단시키는 데 사용할 수 있다.
9
DROP TRIGGER를 실행하면 해당 원본 테이블도 자동 삭제된다.
10
트리거를 너무 많이 사용해도 시스템 동작 추적과 유지보수에는 아무 영향이 없다.

6. 수업 끝 이야기

🌙 시인의 이야기 — 한 단어가 마음의 트리거가 된다

시의 짧은 한 구절이 오래된 기억을 불러오기도 합니다. 데이터베이스의 트리거도 작은 사건 하나에 반응합니다. 다만 “시험”이라는 단어에 자동으로 졸음이 실행되는 트리거는 삭제가 필요합니다.

📖 소설가의 이야기 — 변화에는 전과 후가 있다

인물이 성장하려면 이전의 모습과 달라진 모습이 함께 보여야 합니다. OLD와 NEW는 데이터의 성장 전후를 기록하는 소설가의 시선과 같습니다.

🎭 희곡인의 이야기 — 대사 하나가 다음 장면을 움직인다

무대에서는 한 배우의 대사가 조명과 음악, 다음 배우의 움직임을 시작하게 합니다. 트리거는 데이터베이스 무대의 정확한 큐 사인입니다.

🎬 연극인의 이야기 — 자동 장치는 보이지 않을 때 가장 빛난다

관객은 무대 뒤 장치를 보지 못하지만 장면이 자연스럽게 바뀌는 순간 그 정교함을 느낍니다. 좋은 트리거도 조용히 일하면서 데이터의 질서를 지킵니다.

🎼 음악인의 이야기 — 같은 음을 넣어도 화음은 규칙에 따라 달라진다

함수는 입력된 음을 정해진 화음으로 바꾸는 작곡 규칙과 같습니다. 단, 트리거가 너무 많으면 데이터베이스가 교향곡보다 복잡한 즉흥 연주를 시작할 수 있습니다.

오늘의 오래 남는 마지막 이야기

우리의 삶에도 작은 사건이 큰 변화를 시작하는 순간이 있습니다. 한 번의 질문, 한 사람의 격려, 한 줄의 코드가 미래의 방향을 바꿀 수 있습니다.

좋은 트리거는 변화가 일어났을 때 더 나은 행동을 자동으로 선택하게 합니다. 여러분도 실수했을 때 포기하는 반응 대신 다시 시도하는 반응을, 어려움을 만났을 때 숨는 반응 대신 질문하는 반응을 마음속에 만들어 두십시오. 꿈은 거창한 사건보다 작은 좋은 반응이 반복될 때 현실이 됩니다.
