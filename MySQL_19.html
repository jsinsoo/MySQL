1. 성취기준과 학습 목표

성취기준

문제 상황에서 개체, 속성, 관계와 업무 규칙을 도출하고 이를 ERD로 표현할 수 있다.

일대일·일대다·다대다 관계를 기본키, 외래키, 연결 테이블로 구현하고 SQL 조회를 통해 설계의 타당성을 검증할 수 있다.

학습 목표

  1. 요구사항에서 개체와 속성을 구분한다.
  2. 기본키와 외래키를 적절히 선정한다.
  3. 관계의 카디널리티와 선택성을 판단한다.
  4. ERD를 CREATE TABLE 문으로 구현하고 검증한다.

핵심 질문: 어떤 대상을 독립적인 개체로 볼 것인가, 어떤 정보는 속성으로 둘 것인가, 관계는 몇 대 몇이며 필수인가 선택적인가?

3. 수업 시작 이야기

📚 인문학자의 이야기 — 이름을 붙이는 순간 세계가 보인다

인문학자는 복잡한 현실을 인물, 사건, 장소, 관계로 나누어 이해합니다. 이름을 붙이고 서로의 관계를 설명하는 순간, 흩어진 경험은 하나의 이야기 구조를 갖게 됩니다.

데이터 모델링도 학생, 과목, 교사, 수강이라는 이름을 붙이고 그 사이의 관계를 정리하는 작업입니다. 좋은 모델은 현실을 단순하게 만들되 중요한 의미를 잃지 않습니다.

🏛 철학자의 이야기 — 존재와 관계를 함께 묻는다

철학은 “무엇이 존재하는가?”와 함께 “그 존재들은 어떻게 관계를 맺는가?”를 묻습니다. 존재만 있고 관계가 없다면 세계는 서로 고립된 점들의 모음일 뿐입니다.

ERD는 개체라는 점과 관계라는 선을 함께 그립니다. 한 개체의 정체성과 다른 개체와의 연결을 동시에 생각하게 합니다.

🔬 과학자의 이야기 — 좋은 모형은 현실을 설명하고 예측한다

과학의 모형은 현실을 그대로 복사하지 않습니다. 핵심 변수와 관계를 선택해 복잡한 현상을 이해하고 예측할 수 있게 합니다.

데이터 모델도 마찬가지입니다. 모든 정보를 한 테이블에 쏟아 넣는 것이 아니라, 필요한 개체와 속성만 선택하여 오류가 적고 확장 가능한 구조를 만듭니다.

➗ 수학자의 이야기 — 점과 선으로 구조를 읽는다

그래프 이론에서는 대상은 정점으로, 관계는 간선으로 표현합니다. ERD에서도 개체는 정점처럼, 관계는 간선처럼 연결됩니다.

일대일, 일대다, 다대다의 수학적 구조를 이해하면 복잡한 학교 데이터를 논리적으로 설계할 수 있습니다.

교사의 시작 이야기

오늘 우리는 SQL 문장을 바로 쓰기 전에 현실을 천천히 바라보는 연습을 합니다. 학생, 과목, 수강, 상담, 동아리처럼 익숙한 대상을 어떤 개체로 나눌지, 무엇을 속성으로 둘지, 어떤 관계가 필요한지 결정할 것입니다. 좋은 설계는 코드를 줄이고 오류를 막으며, 나중에 새로운 기능을 추가할 수 있는 여유를 남깁니다.

다대다 관계를 연결 테이블로 구현

학생과 과목의 다대다 관계를 수강 테이블로 분해합니다. 두 외래키를 복합 기본키로 사용해 같은 학생이 같은 과목에 중복 등록되는 것을 막습니다.

CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    enrolled_at DATE,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id)
        REFERENCES students(student_id),
    FOREIGN KEY (course_id)
        REFERENCES courses(course_id)
);

ERD 검증용 조인 조회

설계한 학생-수강-과목 관계가 올바른지 조인으로 검증합니다. ERD의 선과 관계가 실제 SQL 조회에서도 자연스럽게 연결되어야 합니다.

SELECT s.student_name,
       c.course_name,
       e.enrolled_at
FROM students AS s
JOIN enrollments AS e
    ON s.student_id = e.student_id
JOIN courses AS c
    ON e.course_id = c.course_id;

6. 수업 끝 이야기

🌙 시인의 이야기 — 선 하나에도 마음이 있다

ERD의 선은 단순한 연결선이 아닙니다. 학생과 과목 사이에는 배움이 있고, 교사와 반 사이에는 책임이 있습니다. 다만 선을 너무 많이 그으면 ERD도 거미줄도 청소가 필요합니다.

📖 소설가의 이야기 — 인물 관계도가 이야기를 살린다

훌륭한 소설은 인물만 많다고 완성되지 않습니다. 누가 누구와 어떤 관계인지 분명해야 이야기가 살아납니다. 데이터베이스도 인물 소개만 길고 관계가 없으면 조회할 장면이 없습니다.

🎭 희곡인의 이야기 — 역할이 분명하면 무대가 흔들리지 않는다

배우마다 역할이 분명하고 출입 순서가 정리되어야 공연이 자연스럽습니다. 테이블도 역할과 키가 분명해야 데이터가 무대 뒤에서 서로 부딪히지 않습니다.

🎬 연극인의 이야기 — 주인공 혼자서는 공연이 되지 않는다

한 테이블에 모든 역할을 맡기면 주인공이 조명도 켜고 표도 팔고 북도 쳐야 합니다. 개체를 나누고 관계를 연결하면 각 테이블이 자기 역할에 집중할 수 있습니다.

🎼 음악인의 이야기 — 화음은 서로 다른 음의 좋은 관계다

같은 음만 계속 나오면 곡은 단순해집니다. 서로 다른 음이 질서 있게 연결될 때 화음이 됩니다. 테이블도 각자의 개성을 지키며 외래키로 연결될 때 아름다운 데이터의 화음을 만듭니다.

오늘의 오래 남는 마지막 이야기

여러분의 삶도 하나의 거대한 ERD와 닮았습니다. 가족, 친구, 교사, 꿈, 실패와 도전이 서로 연결되어 지금의 여러분을 만듭니다. 어떤 관계는 필수이고 어떤 관계는 선택적이며, 어떤 관계는 시간이 지나며 새롭게 생깁니다.

중요한 것은 모든 사람과 연결되는 것이 아니라, 나에게 의미 있는 관계를 정직하고 건강하게 설계하는 것입니다. 여러분은 아직 완성된 테이블이 아니라 계속 확장되는 훌륭한 데이터 모델입니다. 오늘의 작은 선택이 내일의 기본키가 되고, 진심 어린 관계가 미래의 외래키가 될 것입니다.
