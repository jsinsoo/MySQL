1. 성취기준과 학습 목표

성취기준

저장 프로시저의 개념과 필요성을 이해하고 반복되는 SQL 작업을 하나의 이름 있는 절차로 정의하고 호출할 수 있다.

IN·OUT·INOUT 매개변수와 조건문·반복문을 활용하여 입력에 따라 동작하는 프로시저를 설계하고 관리할 수 있다.

학습 목표

  1. 저장 프로시저의 개념과 장점을 설명한다.
  2. CREATE PROCEDURE와 CALL을 사용한다.
  3. IN·OUT·INOUT 매개변수의 차이를 구분한다.
  4. IF, CASE, WHILE을 활용해 업무 절차를 구현한다.

3. 수업 시작 이야기

📚 인문학자의 이야기 — 반복되는 의식은 공동체의 기억이 된다

인문학에서 의식과 전통은 사람들이 같은 행동을 매번 처음부터 설명하지 않아도 의미를 공유하게 합니다. 좋은 절차는 공동체의 경험을 저장합니다.

저장 프로시저도 자주 반복되는 SQL 절차를 이름으로 묶어 데이터베이스 안에 기억하게 합니다. 개인의 즉흥적 실행을 조직의 일관된 작업으로 바꾸는 장치입니다.

🏛 철학자의 이야기 — 생각은 절차가 될 때 실천이 된다

좋은 생각도 구체적인 순서와 조건이 없으면 행동으로 이어지기 어렵습니다. 철학은 삶의 원칙을 실제 선택의 기준으로 바꾸는 일을 중요하게 여깁니다.

프로시저 안의 IF, CASE, 반복문은 업무 원칙을 실행 가능한 절차로 변환합니다. 무엇을 언제 어떻게 처리할지 명확히 정의합니다.

🔬 과학자의 이야기 — 표준 절차는 실험의 신뢰성을 높인다

과학 실험은 연구자마다 마음대로 순서를 바꾸지 않습니다. 같은 조건과 절차를 사용해야 결과를 비교하고 재현할 수 있습니다.

저장 프로시저는 데이터 처리 과정을 표준화하여 누가 실행해도 같은 규칙을 적용하도록 돕습니다. 반복 가능성은 신뢰성의 중요한 조건입니다.

➗ 수학자의 이야기 — 함수는 복잡한 과정을 하나의 이름으로 묶는다

수학의 함수는 복잡한 계산 규칙을 하나의 기호로 표현합니다. 입력을 주면 정해진 절차에 따라 결과를 만듭니다.

저장 프로시저 역시 매개변수를 입력받고 여러 SQL과 조건을 수행합니다. 복잡성을 감추면서도 논리적 구조를 분명하게 드러냅니다.

교사의 시작 이야기

오늘 우리는 SQL 문장을 많이 쓰는 법보다, 반복되는 일을 믿을 수 있는 절차로 만드는 법을 배웁니다. 능숙한 사람은 모든 일을 혼자 기억하지 않습니다. 중요한 과정을 이름 붙이고, 순서를 정하고, 다른 사람도 사용할 수 있게 만듭니다. 저장 프로시저는 데이터베이스 안에 남기는 친절한 작업 설명서입니다.

IN 매개변수 사용

외부에서 학년 값을 입력받는 IN 매개변수를 사용합니다. 호출할 때 전달한 값에 따라 조회 결과가 달라집니다.

DELIMITER //

CREATE PROCEDURE find_student_by_grade(
    IN p_grade INT
)
BEGIN
    SELECT student_id,
           student_name,
           grade
    FROM students
    WHERE grade = p_grade;
END //

DELIMITER //

CREATE PROCEDURE count_students(

INOUT 매개변수 사용

INOUT 매개변수는 값을 입력받고 수정된 결과를 다시 외부로 돌려줍니다. 80점에 5점을 더해 85점으로 변경합니다.

DELIMITER //

CREATE PROCEDURE add_bonus(
    INOUT p_score INT
)
BEGIN
    SET p_score = p_score + 5;
END //

DELIMITER ;

SET @score = 80;
CALL add_bonus(@score);
SELECT @score;

IF 조건문 사용

점수 구간에 따라 서로 다른 결과를 반환합니다. 저장 프로시저 안에서 업무 규칙을 조건문으로 표현할 수 있습니다.

DELIMITER //

CREATE PROCEDURE check_score(
    IN p_score INT
)
BEGIN
    IF p_score >= 90 THEN
        SELECT '우수' AS result;
    ELSEIF p_score >= 60 THEN
        SELECT '통과' AS result;
    ELSE
        SELECT '보충 필요' AS result;
    END IF;
END //

DELIMITER ;

CALL check_score(85);

CASE문 사용

CASE문으로 입력된 학년에 따라 서로 다른 메시지를 반환합니다. 값 중심의 다중 분기를 간결하게 표현할 수 있습니다.

DELIMITER //

CREATE PROCEDURE grade_message(
    IN p_grade INT
)
BEGIN
    CASE p_grade
        WHEN 1 THEN SELECT '새로운 시작';
        WHEN 2 THEN SELECT '성장의 중심';
        WHEN 3 THEN SELECT '도약의 시기';
        ELSE SELECT '학년 정보 확인';
    END CASE;
END //

DELIMITER ;

CALL grade_message(2);

07

WHILE 반복문 사용

DECLARE로 지역 변수를 만들고 WHILE문으로 1부터 지정한 수까지 반복합니다. 프로시저 내부에서 반복 작업을 수행하는 예입니다.

DELIMITER //

CREATE PROCEDURE make_numbers(
    IN p_limit INT
)
BEGIN
    DECLARE i INT DEFAULT 1;

    WHILE i <= p_limit DO
        SELECT i AS number_value;
        SET i = i + 1;
    END WHILE;
END //

DELIMITER ;

CALL make_numbers(3);

08

프로시저에서 데이터 수정

학생 번호와 새 학년을 입력받아 특정 행을 수정합니다. 데이터 변경 프로시저는 권한과 입력값 검증을 함께 고려해야 합니다.

DELIMITER //

CREATE PROCEDURE update_student_grade(
    IN p_student_id INT,
    IN p_new_grade INT
)
BEGIN
    UPDATE students
    SET grade = p_new_grade
    WHERE student_id = p_student_id;
END //

DELIMITER ;

CALL update_student_grade(101, 2);

5. 형성평가 OX 퀴즈 10개

1
저장 프로시저는 여러 SQL 문을 이름으로 묶어 재사용할 수 있게 한다.
2
CALL 문은 저장 프로시저를 실행할 때 사용할 수 있다.
3
IN 매개변수는 외부에서 값을 전달받는 데 사용된다.
4
OUT 매개변수는 프로시저 내부의 결과를 외부로 전달할 수 있다.
5
INOUT 매개변수는 입력과 출력 역할을 함께 수행할 수 있다.
6
저장 프로시저 안에서는 IF나 WHILE을 사용할 수 없다.
7
DELIMITER 변경은 프로시저 본문의 세미콜론과 전체 문장의 끝을 구분하는 데 도움을 준다.
8
DROP PROCEDURE는 항상 원본 테이블도 함께 삭제한다.
9
저장 프로시저는 반복 SQL을 표준화하고 관리하는 데 도움을 줄 수 있다.
10
입력값 검증 없이 데이터 수정 프로시저를 사용해도 항상 안전하다.

6. 수업 끝 이야기

🌙 시인의 이야기 — 후렴은 감정을 저장한 프로시저다

노래와 시의 후렴은 반복될 때마다 같은 문장이지만 조금씩 다른 울림을 줍니다. 저장 프로시저도 같은 절차를 반복하지만 입력에 따라 다른 결과를 만듭니다. 다만 숙제 제출 프로시저는 자동 호출이 아직 어렵습니다.

📖 소설가의 이야기 — 인물에게는 저마다의 행동 규칙이 있다

좋은 소설의 인물은 장면마다 전혀 다른 사람이 되지 않습니다. 성격과 경험에 따라 일정한 선택을 합니다. 프로시저는 데이터가 장면마다 흔들리지 않도록 행동 규칙을 제공합니다.

🎭 희곡인의 이야기 — 대본은 배우를 가두지 않고 함께 움직이게 한다

대본이 없으면 배우들은 자유롭지만 같은 장면에 도착하기 어렵습니다. 프로시저도 사용자를 가두는 것이 아니라 공동 작업의 방향을 맞춥니다.

🎬 연극인의 이야기 — 무대 전환에는 이름 붙은 신호가 필요하다

조명이 바뀌고 막이 움직이며 음악이 시작되는 복잡한 절차도 “장면 전환 시작”이라는 하나의 신호로 실행됩니다. CALL은 데이터베이스 무대의 큐 사인입니다.

🎼 음악인의 이야기 — 악보는 반복을 지루함이 아니라 질서로 바꾼다

연주자는 같은 음형을 반복하면서도 박자와 강약을 지킵니다. 프로시저도 반복 작업에 질서를 부여합니다. 단, 무한 WHILE은 앙코르가 끝나지 않는 공연과 비슷합니다.

오늘의 오래 남는 마지막 이야기

우리는 반복되는 실수 때문에 자신이 성장하지 못한다고 생각할 때가 있습니다. 그러나 반복은 실패의 증거가 아니라 아직 좋은 절차를 만들지 못했다는 신호일 수 있습니다.

매일 해야 하는 작은 일을 자신만의 프로시저로 만들어 보십시오. 시작 조건을 정하고, 어려울 때의 IF문을 준비하고, 지쳤을 때 멈출 기준도 넣으십시오. 꿈은 거대한 한 번의 실행보다 작은 좋은 절차를 꾸준히 CALL할 때 현실이 됩니다. 여러분 안에는 아직 이름 붙이지 않은 훌륭한 가능성의 프로시저가 많이 남아 있습니다.
