1. 성취기준과 학습 목표

성취기준

관계형 데이터베이스 관리 시스템에서 데이터베이스를 생성·조회·선택·삭제하고, 문자 집합과 정렬 규칙 등 기본 설정을 확인할 수 있다.

데이터베이스 관리 명령의 결과와 위험성을 이해하고 목적에 맞는 이름과 안전한 실행 순서를 적용할 수 있다.

학습 목표

  1. 데이터베이스 목록을 확인하고 목적이 드러나는 이름으로 새 데이터베이스를 생성한다.
  2. USE와 SELECT DATABASE()를 활용해 현재 작업 위치를 확인한다.
  3. 문자 집합과 정렬 규칙의 의미를 이해하고 생성 설정을 검증한다.
  4. DROP DATABASE의 영향을 설명하고 연습용 데이터베이스를 안전하게 삭제한다.

핵심 질문: 데이터를 담기 전에 목적과 경계를 분명히 해야 하는 이유는 무엇일까?

3. 수업 시작 이야기

📚 인문학자의 이야기 — 기억을 담는 그릇

인류는 오래전부터 기억을 보존하기 위해 그릇을 만들었습니다. 점토판, 두루마리, 책, 도서관은 시대마다 모습은 달랐지만 공통된 질문을 품고 있었습니다. “무엇을 어디에 담아야 다시 찾을 수 있을까?”

오늘 만드는 데이터베이스도 단순한 빈 공간이 아닙니다. 이름을 붙이는 순간 목적이 생기고, 문자 집합을 정하는 순간 어떤 언어와 문화를 받아들일지 결정되며, 선택하고 삭제하는 순간 책임이 따릅니다. 데이터베이스를 만든다는 것은 정보를 담을 그릇의 철학을 설계하는 일입니다.

🏛 철학자의 이야기 — 아리스토텔레스의 범주

아리스토텔레스는 세계를 이해하기 위해 서로 다른 대상을 분류하고 이름을 붙였습니다. 이름은 단순한 표지가 아니라 생각의 경계를 만드는 도구였습니다. 무엇을 같은 범주에 넣고 무엇을 구분할 것인지 결정할 때 지식의 구조가 생겼습니다.

CREATE DATABASE school_db;라는 한 줄도 같은 일을 합니다. 흩어진 학생·수업·성적 정보를 앞으로 하나의 목적 아래 모으겠다는 선언입니다. 좋은 이름은 짧지만, 그 안에 설계자의 의도가 선명하게 담겨 있습니다.

🔬 과학자의 이야기 — 린네의 이름 짓기

생물학자 칼 폰 린네는 생물에게 체계적인 이름을 붙여 세계 곳곳의 연구자가 같은 대상을 혼동 없이 이야기할 수 있게 했습니다. 이름이 통일되자 지식은 개인의 기록을 넘어 공동의 과학이 되었습니다.

데이터베이스 이름도 마찬가지입니다. db1보다 school_db, science_lab_db처럼 목적이 드러나는 이름은 협업을 돕습니다. 이름을 잘 짓는 일은 사소한 장식이 아니라 미래의 오류를 예방하는 과학적 태도입니다.

➗ 수학자의 이야기 — 칸토어의 집합

수학자 게오르크 칸토어는 서로 관련된 대상을 하나의 집합으로 바라보는 방법을 발전시켰습니다. 집합은 단순히 모아 놓은 상자가 아니라, 어떤 원소가 속하고 속하지 않는지를 분명히 하는 사고의 틀입니다.

데이터베이스도 하나의 큰 집합처럼 작동합니다. 학생 정보는 학생 데이터베이스에, 실험 기록은 실험 데이터베이스에 담습니다. 경계를 분명히 하면 데이터는 길을 잃지 않고, 우리는 필요한 순간 더 정확하게 찾을 수 있습니다.

교사의 시작 이야기

오늘 우리는 데이터를 입력하기 전에 먼저 집을 지을 것입니다. 집을 잘 짓는 사람은 벽돌부터 쌓지 않습니다. 이름을 정하고, 용도를 생각하고, 어떤 사람이 들어와 살지 상상합니다. 데이터베이스를 만드는 한 줄의 명령은 짧지만, 그 안에는 앞으로 저장될 수많은 정보의 질서와 책임이 들어 있습니다. 이제 우리만의 데이터 세계에 첫 번째 주소를 만들어 봅시다.

5. 형성평가 OX 퀴즈 10개

1
SHOW DATABASES;는 현재 서버에 존재하는 데이터베이스 목록을 확인하는 명령이다.
2
CREATE DATABASE school_db;를 실행하면 school_db가 자동으로 선택된다.
3
IF NOT EXISTS는 같은 이름의 데이터베이스가 이미 있을 때 중복 생성 오류를 줄여 준다.
4
utf8mb4는 한글과 이모지를 포함한 다양한 문자를 저장하는 데 적합하다.
5
USE school_db;는 school_db를 삭제하는 명령이다.
6
SELECT DATABASE();는 현재 선택된 데이터베이스를 확인한다.
7
SHOW CREATE DATABASE school_db;는 데이터베이스의 문자 집합 설정을 확인하는 데 활용할 수 있다.
8
SHOW TABLES FROM school_db;는 school_db의 테이블 목록을 확인한다.
9
DROP DATABASE는 내부 데이터를 보존한 채 이름만 지운다.
10
DROP DATABASE IF EXISTS를 사용해도 실제 삭제 전 대상 이름을 확인해야 한다.

6. 수업 끝 이야기

🌙 시인의 이야기 — 이름을 부르는 순간

김춘수의 시가 오래 남는 까닭은 이름을 부르는 일이 존재를 의미 있게 만든다는 사실을 보여 주기 때문입니다. 오늘 우리는 school_db라는 이름을 불렀고, 아무것도 없던 공간은 배움의 정보를 기다리는 장소가 되었습니다. 여러분도 아직 완성되지 않았지만, 자신의 꿈에 이름을 붙이는 순간부터 그 꿈은 방향을 갖기 시작합니다.

📖 소설가의 이야기 — 톨킨의 세계 만들기

소설가는 이야기를 쓰기 전에 지도를 그리고, 나라의 이름을 짓고, 인물들이 살아갈 세계의 규칙을 정하기도 합니다. 데이터베이스 생성도 작은 세계관 만들기입니다. 오늘은 아직 등장인물도 사건도 없지만, 무대가 생겼기 때문에 다음 이야기가 시작될 수 있습니다.

🎭 희곡의 이야기 — 막이 오르기 전 빈 무대

빈 무대는 아무것도 없는 곳처럼 보이지만, 사실은 모든 가능성이 기다리는 공간입니다. SHOW TABLES;의 빈 결과도 실패가 아닙니다. “아직 아무 테이블도 없으니, 이제 무엇이든 제대로 만들 수 있습니다”라는 가장 깨끗한 출발입니다.

🎬 연극인의 이야기 — 퇴장도 책임 있게

좋은 배우는 등장만 멋지게 하지 않습니다. 자신의 장면이 끝나면 다음 배우가 빛날 수 있도록 정확히 퇴장합니다. DROP DATABASE도 마찬가지입니다. 만들 줄 아는 능력만큼 지울 때 책임지는 태도가 중요합니다. 단, 무대 전체를 철거하는 명령이니 커튼콜 전에 누르지는 맙시다.

🎼 음악인의 이야기 — 침묵에서 시작되는 음악

음악은 첫 음이 나오기 전의 침묵에서 시작합니다. 오늘 생성한 빈 데이터베이스는 그 침묵과 같습니다. 아무 소리도 없지만, 앞으로 학생·도서·실험 데이터가 각자의 음색으로 들어와 하나의 교향곡을 만들 준비를 마쳤습니다.

오늘의 오래 남는 마지막 이야기

오늘 CREATE DATABASE를 여러 번 실행하다 “이미 존재합니다”라는 메시지를 만났나요? MySQL은 여러분의 창의성을 무시한 것이 아니라, “선생님, 그 집은 아까 이미 지으셨습니다”라고 예의 바르게 알려 준 것입니다.

빈 데이터베이스를 만든 사람은 아직 많은 것을 저장하지 않았지만, 무엇을 어떻게 담을지 결정할 권리와 책임을 얻었습니다. 여러분의 미래도 비슷합니다. 지금 비어 있는 부분은 부족함이 아니라 아직 쓰이지 않은 가능성입니다.

오늘 만든 데이터베이스처럼, 여러분의 꿈에도 분명한 이름을 붙이고 하나씩 내용을 채워 가길 바랍니다. 빈 공간은 두려움이 아니라 미래가 들어올 자리입니다.
